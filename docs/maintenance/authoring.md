# 스킬 작성 지침

이 저장소에서 스킬의 규칙과 예제를 추가하거나 수정할 때 읽는다. 일반 스킬 사용 지침에 이 유지보수 절차를 포함하지 않는다.

- 공식 API 제약과 개인 취향을 구분한다. 공식 예제의 스타일을 개인 필수 규칙으로 간주하지 않는다.
- Feature 예제는 사용자 기준 코드와 확정한 취향을 바탕으로 추가한다. 검토 버전, 근거 및 컴파일 검증 여부를 기록한다.
- Effect나 Navigation 등 주제별 문서는 실제 내용이 생길 때 추가하고 SKILL.md에 읽어야 하는 조건을 연결한다.
- 테스트 지침과 테스트 예제는 현재 범위에서 제외한다.
- 버전 관련 근거 확인에는 [버전 기준](version-baseline.md)을, 기준 변경에는 [업데이트 절차](version-updates.md)를 사용한다.

## 규칙 작성 형식

새 규칙은 다음 정보를 갖도록 작성한다. 구체적인 코드가 선택의 차이를 설명할 때 Do/Don't 코드 쌍을 추가한다.

- **규칙:** 한 문장으로 표현한 선택 기준
- **분류:** 공식 API 제약 또는 개인 컨벤션
- **강도:** 필수 / 기본값 / 조건부
- **적용 조건:** 어떤 변경에서 적용하는가
- **Do / Don't:** 같은 상황에서 권장하는 선택과 피하는 선택
- **이유와 예외:** 이 선택의 이점, 적용하지 않는 상황
- **근거:** 사용자 결정 또는 공식 소스의 커밋 고정 링크
- **검토 버전:** 이 규칙의 API·동작을 확인한 TCA 버전

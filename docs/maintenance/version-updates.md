# TCA 버전 업데이트 절차

이 저장소에서 스킬을 유지보수하며 기준 버전 업데이트 또는 새 버전의 영향 분석을 요청받았을 때만 적용한다. 일반 Feature 구현 시에는 이 문서를 읽거나 diff를 조회하지 않는다. 이 문서 자체는 주기적 감시나 자동 업데이트를 설정하지 않는다.

## 1. 비교 기준 확정

- [버전 기준](version-baseline.md)에서 기존 태그와 SHA를 읽는다.
- 사용자가 지정한 후보 릴리스의 태그와 SHA를 공식 저장소에서 확인한다. 최신 버전을 요청했다면 공식 릴리스 목록에서 안정 릴리스를 확인한다. 프리릴리스는 명시적으로 요청한 경우에만 선택한다.
- 기존 태그가 기록한 SHA와 다르게 해석되면 기록을 덮어쓰지 않는다. 차이를 보고하고, 기록된 SHA를 기존 비교 기준으로 유지한다.
- 후보를 조회하지 못하거나 diff가 불완전하면 확인 범위와 누락을 기록한다. 기준 버전은 유지한다.

## 2. 릴리스 노트와 실제 diff 확인

- 두 SHA 사이의 compare를 확인한다: `https://github.com/pointfreeco/swift-composable-architecture/compare/BASE_SHA...TARGET_SHA`.
- 여러 릴리스를 건너뛰면 중간 릴리스 노트와 마이그레이션 안내도 확인한다.
- 변경 파일 목록의 페이지 누락이나 잘린 patch를 확인한다. 필요하면 각 파일의 이전·이후 내용을 조회하거나 로컬 Git diff로 보완한다.
- API 변경·삭제·deprecation, 런타임 동작 변경, 매크로, 공식 문서·예제, 패키지 설정과 버전별 manifest를 검토한다. 패치 버전이라는 이유로 영향이 없다고 가정하지 않는다.
- 상류 테스트 변경은 동작 변화의 근거가 될 때 읽을 수 있다. 이를 개인 테스트 지침이나 예제로 옮기지는 않는다.

## 3. 스킬 영향 분류

현재 존재하는 규칙·예제와 연결하여 다음을 구분한다.

| 분류 | 판단 기준 | 처리 |
| --- | --- | --- |
| 수정 필요 | 현재 규칙·예제가 틀리거나 호환되지 않음 | 해당 내용과 예제를 갱신 |
| 선택적 개선 | 새 API가 대안을 제공하지만 기존 구현도 유효함 | 장단점을 설명하고 필요할 때만 채택 |
| 영향 없음 | 현재 스킬의 지침·예제와 무관함 | 근거만 기록하고 지침은 유지 |
| 미확인 | 소스 누락, 도구 체인 부재 등으로 판단 불가 | 미확인 범위를 기록하고 채택 보류 |

검색할 때 변경된 심볼뿐 아니라 설명된 동작, 관련 의존성 및 예제도 확인한다. 개인 취향은 상류 예제가 바뀌었다는 이유만으로 변경하지 않는다.

## 4. 수정과 검증

- 영향 분석만 요청한 경우에는 결과만 보고하고 기준을 변경하지 않는다.
- 업데이트 요청이라면 필요한 지침과 예제를 수정한다. 대상 앱의 의존성 변경은 별도 요청 범위일 때만 수행한다.
- 변경된 예제가 있다면 후보 버전으로 컴파일을 확인한다. 환경 제약으로 불가능하면 그 사실과 검증되지 않은 범위를 명시하고, 영향을 받는 예제의 검증 버전을 올리지 않는다.
- 스킬 frontmatter, 내부 링크, 남은 이전 버전 표기와 근거 링크를 확인한다. 과거 검토 기록의 버전은 일괄 치환하지 않는다.
- 채택 판단에 필요한 미확인 사항이 남으면 기존 기준을 유지한다.

## 5. 결과 기록과 기준 갱신

실제 검토를 수행했을 때 이 문서 아래에 기록을 추가한다. 빈 검토 기록 파일을 미리 생성하지 않는다.

기록에는 검토일, 기존·후보 버전과 SHA, 릴리스·compare 링크, 변경 요약, 영향받은 로컬 파일과 규칙, 수정 또는 유지 이유, 검증 결과 및 채택·보류 결론을 포함한다.

업데이트 요청에 대한 검토가 완료되면 version-baseline.md의 버전, SHA, 확인일 및 근거 링크와 [SKILL.md](../../skills/brian-tca-feature/SKILL.md)의 사용자용 기준 버전 표시를 함께 갱신한다. 지침에 영향이 없어도 검토를 마친 후보를 새 기준으로 채택할 수 있다. 이 경우 지침은 유지하고 영향 없음의 근거와 기준 변경만 기록한다.
